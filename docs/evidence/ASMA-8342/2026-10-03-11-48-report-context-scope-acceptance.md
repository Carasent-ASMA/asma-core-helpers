## 6. Lifetime and race rules (all consumers)

Invalidate synchronously **before** exposing a new identity-scoped snapshot. Advance generation, make old snapshots/capabilities unusable, detach protected render, cancel requests where possible, unsubscribe owner streams, clear or segregate identity/org/record caches and destroy/reset owner stores. Only after required suppliers and owning authorization resolve for the captured new generation may ready state publish. Abort alone is insufficient: completion/commit handlers compare generation and mount liveness after every await.

| Rule | Required behavior and owner |
| --- | --- |
| **L1 login/initial mount** | Shell assembles only validated session/policy; widgets remain pending/denied until required suppliers resolve. Initial injected metadata cannot satisfy session authority alone. |
| **L2 logout** | Revoke immediately even if signout endpoint fails; clear actor/org/record and protected caches/subscriptions. Late token, wards, record or domain responses cannot resurrect state. |
| **L3 expiry/refresh failure** | Revoke at expiry/denial, not only next interaction. A refresh started before logout/expiry cannot repopulate a later session. Expiry clock tolerance follows owning auth contract, not a new independent auth policy. |
| **L4 actor/role/permissions** | Clear protected prior state and revalidate grants; composition stays role invariant. Same actor ID with changed grants is not permission-cache reuse proof. |
| **L5 organization** | Enter pending and clear before deliberate reauthentication. A→B→A does not restore saved A session/data; failed B reauth does not render A data. One active organization. |
| **L6 record/guardian/self** | On self→participant, self→ward, ward→ward, ward→self or record deselection, clear prior record state first. Keep actor separate; supplier/relationship failure denies. Requests carry correct current owner-authorized record and journal. |
| **L7 navigation/composition** | Route/query/hash/notification request selection only; validate before ready render. Same-identity route change may reuse only data explicitly keyed to that authorized context; composition remount must preserve revocation discipline. |
| **L8 concurrent/late async** | A/B record lookup, guardian lookup, org reauth, token refresh and owner request completion in reverse order: only captured current generation commits. Identity-scoped promise dedup includes context/request semantics; pathname alone is insufficient. |
| **L9 unmount/remount** | Dispose each instance, cancel effects/streams and revoke retained capability references. Cached ESM module or singleton store cannot reuse prior instance data on remount. |
| **L10 reconnect/subscription** | Reconnect revalidates current capability; no old tenant/record stream resumes. Subscription callbacks check generation and cannot refill a cleared store. |
| **L11 cache/multiple widgets** | Owner query/MST/urql/IDB/cache lifetimes include actor/customer/record/grants. Concurrent same-app widgets do not overwrite each other's selected context; shared caches are only shared within a proven identical authorized scope. |
| **L12 anonymous/error/transport** | Public-capability state never inherits protected data. Failed mount/update, missing provider, incompatible binding or error notice cannot expose sensitive props/tokens. Both transports meet the same rules; Artifact's invalid qiankun branch remains denied. |
